# T-MPC++ / SH-MPC 独立修复报告

日期：2026-09-10。本轮由 Codex 直接检查源代码、修改、编译并运行，未采用 CC 的归因作为结论。

## 1. 当前结论

原来 11.33% / 2.50% 的比较包含实质接入和求解器后端错误，不能用于证明我方算法优越。
已完成一轮接入修复和 180 回合六场景开发复验；不是“两个方法已完整验收”，也不是正式论文结果。
五人环境已恢复正常导航，但密集场景仍有性能问题。不能以“必须接近我方分数”作为正确性判据。

## 2. 亲自确认并修复的主要问题

| 问题 | 修改与证据 |
|---|---|
| 终端目标代价未真正启用 | 上游 objective 定义存在，但 acados 的 cost_type_e 被注释；已启用 EXTERNAL，去掉终端不存在的控制输入项。修复后背向目标的空场景也能转向到达。不能再说 T-MPC++ 天生没有目标收敛项。 |
| 路径末端不连续及速度参考缺失 | 修复 Spline2D 越过最后节点后的错误参数，使用末端切线延拓；路径终点为真实目标，接入原生 PathReferenceVelocityModule。 |
| SH 的软约束被误改成硬约束 | FORCES 使用 model.get_xinit()，明确不固定 slack；acados 原来固定全部 nx。已只固定实测状态前缀，slack 由优化决定。五个密集 case 的 321 个控制步全部求解成功，修复前并非如此。 |
| SH 的轨迹分布不等于共享后验 | 旧转换只匹配部分边际方差，丢失跨时间的位置-速度相关。现在直接抽样完整 4D 后验和 CV 加速度过程。80,000 次抽样：理论时间相关 0.804447，实测 0.805261，最大边际方差相对误差 1.10%。 |
| SH 初值被覆盖和索引越界 | 保留 PushAlgorithm/DRProjection 的分支初值，后续只更新参数；移除 scenario_indices 在多障碍循环中的错误缩容，并加入有界索引。 |
| 成功/失败状态读取错误 | 修复重复转换 acados 0 状态为 FORCES 1；nlp_res 原是指针，不可读成 double；显式计算 RTI 非线性残差，失败时复制本次分支状态，不再沿用上次成功值。 |
| 不一致的引导层配置 | 原 ROS 参数仍含 T=6、N=30、v_max=3、a_max=7。现在各进程使用独立命名空间，与本次求解器时域及 v=1、a=2 对齐，不覆盖其他任务的全局参数。 |
| 制动初值不满足动力学/界限 | 原减速度可超过 a_max，v=0 时仍给负加速度。已按限幅及可用速度制动，位移采用速度斜坡；接口自检的积分残差约 6.94e-18。 |
| 角度和初始状态不连续 | 连续展开测量/引导航向，角差改为 atan2(sin,cos)；Contouring 更新 spline 状态后重新设置 xinit。 |
| 比较双方使用不同执行动力学 | 新增可选连续加速 unicycle 执行器及我方匹配 rollout；对所有臂统一 v/a/omega、连续弧线运动和实际人类轨迹碰撞审计。旧默认执行路径不替换。 |
| 末端状态缺少配套参数/界限 | 接入终端约束和状态界限时同步扩展 N+1 参数/初值/约束数组，使用真实末端预测，不复制 N-1 的障碍数据冒充末端。此项是后端建模补全，需要在正式方法版本中明确登记。 |

原始冻结工作区、历史结果和论文文件没有修改。全部原生修改在 build_modern/*_repair* 副本中。

## 3. 实际完成的验证

- Python/原生接口专项测试：7/7 通过，包括连续动力学、航向展开、协方差协议、末端代码生成、SH 初态不锁 slack 和原生参考/制动自检。
- C++ 抽样统计测试通过，使用的是控制器实际调用的采样函数，不是另写的近似复算。
- 两个方法分别通过四类空场景到达检查：正常接近、临近目标横向偏离、侧向起点、背向目标。原来背向目标不能到达。
- 10 个相同五人开发 case（11160-11169，遮挡，统一连续执行）：我方成功 10/10，T-MPC++ 最佳开发档 8/10，SH-MPC 两个开发档均 10/10。这不是显著性或泛化结论。
- 固定设置后，六场景 x 每场景 5 case x 3 臂 x 两种观测条件，共 180 回合完成。具体冻结口径见 VALIDATION_PROTOCOL.md。

## 4. 已否定的修法与尚未解决的问题

- 单纯把 T-MPC++ 换为完整 SQP + 回溯线搜索，没有解决五个密集 case（0/5 成功），未采用该诊断变体作为主版本。
- 2 秒改成 4 秒时域也没有解决这批密集失败，不能声称“只是时域短”。
- 同一失败观测上，我方所选轨迹满足我方风险判据，却违反对手的硬椭圆约束；额外抽样 3000 条可执行轨迹也未找到满足全部椭圆约束的轨迹。这是约束差异线索，不是不可行性的数学证明，也不是 SH 场景可行性证明。
- 五人上的工作点已经恢复正常，但密集场景的风险限制、目标推进和失败处理仍需公平标定/归因。不把困难环境删掉，不通过缩小 sigma 或放大到达半径制造高分。
- SH 必须同时报告 solved、非零 slack、原生安全检查状态、实际执行结果；不能只选其中一个。
- 未完成现代基线的最终独立验收。正式大矩阵不应直接复用旧冻结点，需先完成五人开发标定，再冻结新协议和独立布局。
- 整个代码库的联合测试目前仍有一个已存在的夹具错误：test_bayesian_rfs.py 的旧报告测试没有 age_margin 条目，导致 KeyError；本轮未改该不相关报表逻辑。联合测试 41 项中 39 通过、1 跳过、1 报错；专项原生测试另开后 7/7 通过。
